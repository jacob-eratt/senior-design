# Recorded measurements

## CPU Conv0, October 1, 2026

[cpu_conv0_benchmark.json](cpu_conv0_benchmark.json) records a local run on an
Intel Core i7-13700H, Windows, Python 3.12.2, NumPy 1.26.4, TensorFlow 2.16.1.
Each method uses 25 warmups and 500 separately timed batch-one calls.

| CPU method | Median | 95th percentile |
|---|---:|---:|
| Current NumPy INT8/INT32 correctness reference | 1.260 ms | 2.049 ms |
| TensorFlow FP32 conv+bias on identical integer-valued operands | 1.964 ms | 2.490 ms |

Both outputs were checked against the saved Conv0 accumulator fixture. The
TensorFlow run uses one intra-op and one inter-op CPU thread and includes
`tf.function` dispatch and `.numpy()` materialization. It does not establish
the performance of a tuned CPU INT8 kernel. The NumPy call includes padding,
patch construction, type conversion, and accumulator safety checks.

Timing excludes model/file loading, quantization, ReLU, and transfers to/from
an FPGA. Operands are already in memory. Background load, power management,
and scheduling were not controlled; these are local reference measurements,
not a CPU performance ceiling or a rigorous CPU-versus-FPGA speedup claim.

Reproduce after generating full artifacts, from `resnet8_project/`:

```powershell
..\.venv-resnet\Scripts\python.exe benchmark_conv0.py --tensorflow
```

The output defaults to ignored `resnet8/artifacts/cpu_conv0_benchmark.json`, so
a fresh benchmark does not overwrite this recorded baseline.

## User-reported RTL simulation evidence

These values were supplied from Vivado 2024.2 console logs, not generated by
an agent-run simulation. The corresponding imported project copies were not
independently hashed. Exact source/build reproducibility remains the team's
responsibility when reproducing the runs.

| Design | Reported result | Python fixture | Overall launch |
|---|---|---:|---:|
| Original 27,648-MAC, one-output-channel design | 904,229 comparisons passed | Skipped | 58 min 41 s |
| One-MAC complete Conv0 | 3 frames, 79,872 comparisons passed | Skipped | 40 s |
| 416-MAC complete Conv0 | 5 frames, 133,120 comparisons passed | Skipped | 15 s |

The 416-MAC run reported 8,583 cycles for each of the first two frames and
10,821 / 10,842 / 10,727 cycles for the three stalled frames. The 8,583 count
includes six deliberately stalled final-write cycles. It excludes preload.
The intended stall-free schedule is 8,577 cycles. At an assumed 100 MHz that
would be 85.77 microseconds; clock frequency, resource fit, timing closure,
and actual FPGA latency have not yet been established.

Only the original fully parallel design has supplied synthesis results:
2,916,423 LUTs (2,490.12%), 850,272 registers (362.99%), and zero DSPs. It does
not fit the K26. Resource comparison for the new 416-MAC engine awaits its
synthesis report.
